## Ladybirdがついにアルファ版へ

![screenshot](../img/hero-screenshot-dark.webp)

- [Ladybird Web Browser/Engine Reaches Alpha｜phoronix.com(英語)](https://www.phoronix.com/news/Ladybird-Browser-Alpha)
- [Ladybird is now in alpha｜公式ブログ(英語)](https://ladybird.org/posts/alpha/)
- [Ladybird｜公式](https://ladybird.org/)

Ladybirdは、ChromiumやGecko、webkitなどのフォークではない完全独自開発されたエンジンで、それを内包するブラウザのUI・機能は現時点では<u>控えめだが機能的</u>というような状態となりました。
つまりテスト段階として実際に動作するブラウザとなったということです。ただし、また安定版ではないので表示が崩れたり動かないサイトがあったり、クラッシュする場合もあるという位置づけです。
これらはメインブラウザとして使用するには不安は残るけれども、日常利用では利用できる状態なので何か不具合が発生した場合には報告したりセキュリティ検証への協力が呼びかけられています。

**macOSとLinux向けに提供されており**、これまでのように毎回ソースからビルドをしなくても試せるようになっています。
Linux向けにはFlatpakやUbuntu・Fedora向けバイナリ等が用意され、ローリングチャネルで自動更新も行われます。

<u>独自エンジンを載せて実際に触れる状態になった初期テスト版ブラウザ</u>という位置づけです。

### どういうロードマップが用意されているか

<div class="table-container">

|マイルストーン(時期)|ターゲット・位置づけ|
|--------------------|--------------------|
|Alpha(2026年現在)|Linux / macOS 向け。早期導入者や開発者が日常のテストや不具合報告に使う段階|
|Beta(2027年)|Linux / macOS 向け。機能や互換性が大きく拡充され、より広いユーザーが実用を試せる段階|
|Stable(安定版・2028年)|一般ユーザー向けの正式リリース。メインブラウザとして日常利用できる品質を目指す|

</div>

LinuxとmacOSが最優先ターゲットであり、Windowsネイティブ版は安定版に向けた優先度としては<u>後回し</u>になっています。どうしても利用を考えている場合はWSL2での動作を案内という方針です。

> Windowsが後回しになっている理由
> 一つは、ブラウザをゼロから作るようなC++やRustのシステムプログラマは、日常の開発環境としてLinuxやmacOSを使っている人が圧倒的多数ということが言えると思います。一つは、WindowsはUNIX系とはまったく異なる独自の設計思想（Win32 API / NTカーネル）で作られているため、マルチプロセス設計のブラウザをネイティブ対応させようとすると、OS固有の壁にぶつかるという点が挙げられると思います。
> 最終的には対応させるとしても、まずは完成させる方が優先されるのは当然です。巨大な開発チームでやっているのではなく少数精鋭で開発されているというのも理由なのかも知れません。

現在のWebは、仕様書通りの実装だけでなく既存ブラウザが長年引きずっている独自の挙動に依存しているサイトが多くあり、アルファ版ではユーザーから送られる「表示が崩れる・動かない」サイト等の報告や、数百万件に及ぶWeb Platform Tests(WPT)の検証を通じて、あらゆるサイトが破綻なく動く互換性を積み上げていっている段階です。
またゼロから開発されているブラウザでは過去の遺産のようなものもないため、セキュリティとメモリ安全性を高めるため既存のC++コードベースからRustへの移行が進められています。
既にJavaScriptエンジンのパーサーやバイトコード生成機がRust化されており、今後はスタイルやレイアウトエンジンなどの他の重要なコンポーネントも順次Rustへ置き換わり、脆弱性やクラッシュの少ない堅牢な構造へと進化していってます。

話によると、「セキュリティの保証無し」とされている新参者の状態を脱却するため、外部のセキュリティ専門機関との連携や研究者からの脆弱性報告プログラムを通じてセキュリティの強化も行っているそうです。
これらはプロセス分離(GPU隔離やサンドボックス化)も更に詰められ、ログインや決済などを含む日常利用に耐えうる安全性を確保しているということです。

ユーザーが見えやすい部分だと、JavaScriptのJIT(実行時コンパイル)の最適化、WebAssemblyエンジンの刷新、ハードウェアデコード、コンポジターの高速化など、パフォーマンス面が他の商用ブラウザに近づくように磨き上げられている所です。
同時にUIの洗練や基本機能も<u>控えめだが機能的</u>な最小構成から、日常使いに不足ない完成度へと引き上げられています。

これらLadybirdは、

- 非営利団体(Ladybird Browser Initiative)として運営されている
- Firefoxのようなデフォルト検査契約をせず
- Chrome・Braveのような広告・暗号資産などの収益化モデルを持ち込まず

純粋なWebブラウザのまま2028年の安定版到達を目指すのが特徴です。

### 余計な機能(ブロートウェア)が一切載っていないブラウザ

現在のブラウザは、本来のWebページを表示するという役割を超え、多機能化・肥大化が進んでいます。

- 生成AIアシスタント、暗号化資産(Web3)ウォレット、VPN、ショッピングクーポン機能、独自ニュースフィード、クラウドアカウント連携なとが標準で組み込まれており、設定でオフにしてもコード自体は残り続けます。
- Ladybirdは、純粋にWebを閲覧するための道具に徹しています。機能が少ない分、<u>起動や動作が軽快</u>だけでなく、攻撃対象領域が圧倒的に小さく、複雑な機能同士の干渉による<u>バグや脆弱性も生まれにくい構造</u>になっています。

既存ブラウザが重く複雑になっている最大の理由は、1990～2000年代から継ぎ足されてきた膨大なレガシーコード((古い仕様や互換性維持のためのコード))を抱えているためです。

- Chromium(Bink)やFirefox(Gecko)は数千万規模の巨大なコードベースになっており、少し手を入れるだけでも膨大なコストとリスクが伴います
- Ladybirdは、<u>現代のWeb標準とハードウェア環境を前提</u>にゼロからスクラッチで設計されています。更に、メモリ安全性に優れたRustへの移行も前提に含まれているため、過去のしがらみに縛られない<u>クリーンでモダンな設定が可能</u>となっているわけです

ブラウザの肥大化は開発元の収益モデルと直結しています。

- Google(広告事業)が主導するChromium系ブラウザは、Web標準の策定や広告ブロック制限(Manifest V3など)においてビジネス上の利害が絡んでいます。Firefoxも検索エンジン契約(Googleからの資金提供)や新規収益事業の模索に影響を受けざるを得ません
- Ladybirdは、非営利団体として<u>スポンサー企業や個人からの寄付のみで運営</u>されており、ユーザーデータの収集(テレメトリ)、広告配信、特定の検索エンジンへの誘導といった<u>商業的なインセンティブが一切ありません</u>

現在、Webのルールは事実上Chromiumの実装が基準になりつつありますが、特定の1社がWebの仕組みを独占することは健全ではありません。
Ladybirdは、「大企業の傘下につくということなく、かつLinuxでも動く完全新規の独立エンジン」として、Webの多様性と健全性を守る最後の砦のように期待されています。

### 安定版になったらどうなる？

HTML・CSS・JavaScriptといった「通常のWebサイトやWebアプリを動かす標準仕様」に関しては、2028年の安定版（Stable）の段階で他ブラウザから乗り換えられるレベルの高い互換性に到達する可能性が非常に高いと考えられています。
しかし、標準の外にある動画配信のDRMや拡張機能などに関しては乗り換えに躊躇してしまう場面が残されているという現実的な見通しもあります。

- 現時点でのテストでは、Safariに迫る、あるいは一部上回るスコアを記録する段階まで来ています。
- Gmail、Instagram、Slack、YouTube、Twitch、Photopea（ブラウザ版Photoshopクローン）といった非常に複雑なJS・CSSを駆使するWebアプリがすでに動作・表示改善の対象として実際に動かされています
- Googleなどが先導して事実上の標準になっている独自挙動や、`@-webkit-`系の古いベンダープレフィックス、さらにはサイト側がブラウザを弾く問題に対するUser-Agentの工夫など、泥臭い互換性対応も積極的に行われています

こういった理由から、安定版になる頃には、ニュースサイト、SNS、プログ、一般的なWebサービスなど日常で見る95%以上のサイトのJS/CSSは他のブラウザと遜色なく動くと、ある意味楽観的な見解ですが、そう言われています。

普段は軽いブラウザで日常使いして、特殊な用途(DRMが必要なサイト、ブラウザ拡張機能、Chromeでしか動かないような最新のWebツール)では一時的に動かないケースが出ると言えます。

#### 現在で言うとHeliumをメインで使用する感じ

エンジンこそBlinkで、ベースな部分はChromiumですが、Ladybird同様にDRMなどが使用できない[Helium](https://helium.computer/)を使用している感じが現在では近いと思います。
ただこれまでに書いたように、エンジンも全てがゼロから作られているのがLadybirdですから使用感は異なるとは思います。環境的にHeliumを使用していて何ら困らないのであればLadybirdに乗り換えを行っても、安定版となる2028年以降なら有力候補には上がるのではないかと思っています。

Heliumではublock originがネイティブなコンポーネントとして搭載されていますが、作者も言うように<u>サポートができうる限り継続する</u>というような状態になっています。
Ladybirdは、Braveが開発したオープンソースのフィルタリングエンジン(`adblock-rust`)をブラウザ本体に直接組み込んでいます。
外部の拡張機能を経由せずともEasyListなどの標準フィルタリストを読み込み、ネットワークレベルでの通信遮断とCSSによる要素非表示(コスメティックフィルタリング)をネイティブで実行できます。
つまり拡張機能と同等の広告ブロックを拡張機能より高速に、より早い段階で(拡張機能を読み込む前から)実行できるということです。
Googleのように「本業の広告収入を守るためにブラウザの仕様を変える」というような動機が一切ないため、YouTube側が広告表示のロジックを変えても、フィルタリストの更新やブラウザ側の改善で純粋にユーザー側の快適さを優先できます。

Youtubeは広告を表示することがサイト利用のための条件でもありますが、Ladybirdを使用禁止にする以外にYoutube側がブロックはできないということになります。現在でもBraveで閲覧できる以上それらは可能だとしてもほぼ不可能でしょう。

Youtubeでは今はまだ収益の分配が行われているわけですが、配信者や動画の質の低下などが進んだ場合、広告が売れなくなり4K配信も可能にしたインフラの維持などで巨大化したサイトは、サイト自体の維持も難しくなるのではないでしょうか？
そのため、一部のまとめサイトやAI生成の量産動画などの**収益化停止**などが行われ、できるだけ良質な配信者を残そうとする動きが見られます。それは広告を出してくれるスポンサーへの配慮でもあり、サイトを維持するためには大切なことでもあるわけです。
一方で、質の低い動画への配当を切って、本当に人を集められるクリエイターに資金を集めるということ、サブスクリプション・投げ銭への収益の柱を少しずつ広告から移そうという動きも見れます。

結局のところ、動画視聴を邪魔する広告をユーザーは嫌っていると思うのです。一方で、そうしないとYouTube Premiumが売れないとも言えます。ブラウザ自体の機能で広告を消すようになるとYouTube Premiumも売れなくなり広告を出す企業も減れば収益も増えなくなる未来があります。
どうすればそれらがうまくできるかを模索しているとも考えられます。

Youtubeではこうですが、アフィリエイトブログなどは個人が勝手に書いているだけなのでYoutubeのような巨大サイトの運命というほどの被害はありません。たった数行のまとめと広告しか無いサイトのどこに価値があるでしょうか？そういった無駄なトラフィックを食っていたり、ユーザーの視聴の邪魔をするものを無くす、それがLadybirdなどの広告ブロックの本意ではないかと。
決してYoutubeを潰そうとしている機能ではなく、無駄をなくすためのものだとユーザーも理解しやすいと思うのです。

## まとめ

軽量でクリーンなブラウザというのは、元々Chromeが目指していたところだと思います。しかし、どうしてもビジネス的に利益を上げる必要があるという点や傘下の巨大サイト(Youtubeなど)の運営にも絡んだりもするのだと思う所もありますが、そういうしがらみがないとしたらそれはまさに人々が望んでいたものの誕生を、目の当たりにしようとしているのかも知れません。

Wikipediaでは、

GitHubの共同創業者であるクリス・ワンストラス氏の100万ドルの寄付を皮切りに、Cloudflare、Shopify、Proton、37signalsといった「健全でオープンなWebインフラが生き残ること自体に価値を感じる企業や個人」からの純粋な寄付とスポンサーシップのみで運営されています。公式サイトでも「デフォルト検索の契約も、暗号資産トークンも、ユーザーを収益化する仕組みも一切作らない」と明確に宣言しています。

というようなことが書いてあります。

かつて初期のChromeやFirefoxに人々が熱狂した「ただ純粋に速くてクリーンで、ユーザーの味方である道具」という原点を、営利企業のしがらみを構造ごと断ち切った形で現代に作り直そうとしているのがLadybirdです。
私たちが今まさに目の当たりにしているのは、Webの歴史の中でもかなり稀有で理想的な実験の幕開けと言えそうです。
