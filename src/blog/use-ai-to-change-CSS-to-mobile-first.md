今回は閑話休題、これまでの様々なサイトの問題の解決へのお話です。

## もう一度最初から作り直そうかとも思った

「最初からモバイルファーストで作れや」と言う声には耳が痛い次第ですが、それには色々と事情がありまして、昔のように(現代でもありますが)Word Pressのようなあるいは他のブログサービスで1から作るのであれば、そりゃ色々と想定してから作り始めるなどもしますが、11tyで作り始める際に、スターターキットを使用したのである程度はそれに準じて変更を加えていったわけです。

そうするとそれではイマイチになってきて、手を加えだします。

色々困っていた時に、11tyのガイドを見ているとVITEと言う文字が目に入ります。これは、cssやJavaScript、ページのテンプレート(.njk)を変更するとローカルのサーバーに反映させてすぐに変更を見れるというものです。
つまりは開発環境を作る上でこれが動作したら、cssを変更して(ウィンドウのフォーカスが変わったら)保存したら、すぐに該当アドレスのブラウザで変更が適用されますから便利なことこの上ないわけですが、設定がムズいのです。

## 11tyでVITE

元々のスターターキットでは[Tailwindcss](https://tailwindcss.com/)が組み込まれていました。出力する前に[postcss](https://postcss.org/)に通して、必要な形にしてからstyle.cssへ書き出すというようなものです。
しかし、色々と作業を進めていくに当たって、Tailwindcssがそれらを行えると知ったのです。Tailwindcssの[Installation](https://tailwindcss.com/docs/installation/)には、Vite、Postcss、CLI、各フレームワーク、あるいはCDNでの導入方法が書かれてます。11tyは？ねぇ11Tyではどうするの？って話ですよ。

で、更に色々調べて、ここで11tyに[公式プラグインのVite](https://www.11ty.dev/docs/server-vite/)があると知ったのです。で公式(英語ですが)のページを見てもらったらわかりますが、オプションにどんな物があるか、どうすれば導入できるかは書いてありますが、細かくはVITEのドキュメント見てねという感じで、いや、せめてViteが動く所までは書いておいてくれよと、何が必要で11tyとどういう連携しているかを書いておいてくれよと思うのです。

とりあえず入れると、動作はします。エラーも出たりして、それをとりつつ動かすと機能しているように見えます。しかしサーバーのアドレスが変わったり、postcssとの兼ね合いは？tailwindcssもこのままで良いのか？と思うのは当然です。しかしどこにもその答えはないです。
そこでViteを使用しているようなスターターキットを調べて、そのGithubのページから設定を見てみます。しかし、それらの人がcssやjsの管理を同じようにしているわけではありません。しかも記事が古い。

そのため、正解がわからないまま何とか動作するようになってから記事を書いていたりしたわけです。

ある日、AIに聞いてみようと言うことで、ChatGPT、DeepSeek、Geminiなど全部無料版ですが聞いてみると、あれはダメだ、これはダメだとダメ出しされます。それらを通じて、確かGrokにも聞いたでしょうか、その時に「正しくhmrしていない」と、してたらcssなどはブラウザのリロードなしに更新できるようになる、ホットリロードというのが機能するはずだと言うわけです。
なにそれ、ホットリロードってええやん、ということである程度は直し、更に直して、AIのバージョンが上がる度に、どうだろうと今はこうだけどどうすれば正しく動くかを聞くわけです。

やっぱり、あれが足りない、これが足りないと言うばかりでその通りするとたいていエラーが出てそれを取るのに四苦八苦します。ChatGPTは一番使えませんでした。こいつの言うことは情報が古く、しかも回答が正しくない。DeepSkeekも同じような感じでした。
Geminiは大まかに正しく動作するようになりましたが、それでも何かを更新するとcssはhmrが効くが、画像をフォルダに入れてその画像を使用するとすると、内部では変更されているのに、ブラウザには伝わっていないので、一旦接続を切りエディター上で再起動すると反映するという面倒くささでした。
これまで当サイトで画像をあまり使用していなかったのも、できるだけサイト自体を軽くしたいというのもあり、また編集の面倒くささもありで少なかったのです。

これはテンプレートの編集でもそうでした。`src/`の中で作業して、できあがったものは保存するとビルドが走り、dist/にできあがったファイルが書き出され、即ブラウザでそれらを表示するという仕組みですが、テンプレートの編集をして、tailwindcssは、要素の`class`に対応した内容を書けば反映されます。

```html
<span class="text-amber-300">テスト</span>
```

<span class="text-amber-300">テストの結果はこんな感じです</span>

と書けば、この部分が黄色っぽく表示されるわけです。`margin`や`padding`なども`my-[2rem] px-[2rem]`などのように書けるわけです。`style.css`に書く前にチェックもできれば、レスポンシブの設定も書けます。しかし肝心のテンプレートがセーブしても即ブラウザに反映されない。だったらCodepenとかを使ったほうが良いんじゃないかとまでも思う始末です。
