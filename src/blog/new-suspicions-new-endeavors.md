## Dux shell（旧Dank Material Shell）で文字入力あたりに気になる引っ掛かりがある

これまでに2回、Dux(旧DMS)チームに報告をし、それぞれのfixはありました。確かにこれらのfixで最初の状態から見ても、だいぶ度合い的には軽度な状態になったとは感じています。
しかしそれでも尚、短い間隔で回復するものの、ワークスペースの切り替えなどの時に`SUPER + [num]`と数字で切り替えで問題が発症した場合、その画面にThunar(ファイルマネージャー)が起動していたら、ダイレクト検索のインプット欄に「1111122222111113333」みたいな表示が出たりします。
これはそれだけワークスペースを切り替えようと数字を押したと言うことです。

Thunarは画面上で文字をダイレクトに入れてファイル検索ができる機能があり、わざわざインプット欄にフォーカスを当ててから文字入力をすること無くファイルが探せるようになっています。
本来であれば、そういう機能があったとしてもバインド(ショートカットキー)が機能していたらHyprlandの機能が優先して働きますが、それらが機能していない時、あるいは`Super`(Windows/⌘キー)を押していない時はThunarの入力に変わるわけです。
この数字が連続して入力・表示されると言うのはたまたまThunarでそうなだけで、他のアプリ上でも問題が発症してたらバインドは効かなくなります。
この問題が発症してから回復するまでの度合いが、これまでより軽度になったというのがこれまでの経緯です。

長時間のスリープ運用でそうなることが多く、復帰時に以前の状態が残って渋滞を引き起こし新たな入力が阻害されているというような、そんなイメージです。
内部的にどうなっているのかはわかりませんが高速道路の渋滞の動いたり止まったり、それらで高速に乗れなかったりそういう状態から、何かが動いて突然それらができるようになり、しばらくそういう状態が続くと言う感じです。

### 他の環境ではどうなんだろうか

違う環境を試す用にFedora COSMICの入ったSSDがあったので文字入力を試してみました。実はFedora COSMICでも微妙な引っ掛かりがある事にこの時気づいたのです。
しかしCOSMICは安定版になったとは言えど日本語周りはまだ完全に安定しているわけではありません。現行バージョンではなく古いものでしたから確かな情報とは言い切れないものの、エポック1になって安定版になってから入れたものなのでベータバージョンのものでもありません。
また起動も怪しく、セッションが始まらないこともあり、「アップデートしてないしな」と思いつつ、ttyを起動して`start-cosmic`でデスクトップ環境を起動させ、試していました。

しばらくして、

- 問題があるDuxと同じ環境で比較した方が良いのではなかろうか
- CachyOSでかつ<u>最近のGNOMEであればどうなんだろうか</u>

と思うようになり、検証した後も続けて使用することを考え、たまたまCachyOSのライブISOが入ったUSBがあったので新たにGNOMEを入れ直して試してみました。
これにより導入したGNOMEは最新のv51.1になっています。
なぜGNOMEなのかはPlasma環境での問題だった場合に、それらを切り分けるためです。

PlasmaやGNOMEそのものでは引っ掛かりはほぼ経験がなく、うまく動作しているように思いますが、それらを長時間スリープ運用しているわけではないので、Duxで起こるような挙動がそれらであるのかはわかりません。
そこでしばらくスリープさせて使ってみたらどうかとも思いましたが、それらは圧倒的にドットファイル等のプロジェクトよりも多くのフィードバックがあり修正されています。日本語環境で使用している人も多いでしょう。
それならそこを検証するよりも、Duxと同じような構成で実装されている[Caelestia](https://github.com/caelestia-dots/caelestia)を試してみようと思ったわけです。

### アプリ導入時何度もパスワードを求められると面倒なので指紋認証で

GNOMEの設定の一つですが、デスクトップPCだと別で指紋リーダーを用意しないといけないものの、ノートPCでは比較的普通に指紋認証の機能はついていたりします。
指紋を登録しておけば、アプリを入れる時にパスワードを聞いてくる場面で(対応しているものなら)指紋認証で進められるようになります。これらはパスワード入力が強制されているものもあります。

他にも何も設定無しだと10～15分でロック画面に切り替わったりします。ここでもスリープからの復帰の時にパスワードを入力する必要が出てきたりしますが、Caelestiaのロック画面では指紋認証にも対応しているため、指紋認証の方が解除が早い事もあって導入をオススメします。

- GNOMEの「設定」を開きます。設定画面を開く方法はいくつかあります
  1. ドックから
  2. トップバー右側のWi-Fi等アイコンから開いたパネルの中の上部ギアアイコン
  3. アプリケーションメニューで「set」辺りまでダイレクトにキーボードから入れると「設定」の候補が絞られ選択しやすくなります
- 設定メニューの下の方に「システム」だったと思いますがユーザーの管理ができる所があります。
   1. アカウントの追加などもできるためデフォルトではロックされています。
   2. パスワードを入れてロックを解除し、指紋の設定ができる項目があるのでそこから指紋を登録します
      - 左右の 親指・人差し指・中指 などが登録できます。使い勝手の良い指をいくつか登録しておくと良いと思います

CaelestiaのようなAURやGithubからドットファイルをインストールしたりするようなアプリは特に、許可を得るためにパスワードの入力が必要になるため、予め指紋の登録しておくといろいろな場面で時短に繋がるでしょう。
ターミナルからのパスワードの入力は指紋認証が失敗した場合のフォールバックになります。

### 現在のCachyOSではparuがデフォルトで機能しない

CachyOSは最初から**paru**が入っているので、とても簡単にパッケージのインストールを公式のリポジトリ、AURのユーザーリポジトリ関係なくインストールできて良いと言うことをこれまでからも書いてきましたが、現行のCachyOSでは<u>paruはデフォルトで無効</u>になっており、代わって登場した**shelly**からのパッケージの導入を勧めているようです。
かと言って、paruはシステムアップデート時に`paru`と入れるだけで`sudo pacman -Syu`と同等に動きますし、パッケージのインストール・アンインストール時もGUIでshellyを立ち上げて検索して操作するよりよっぽど早くに色々できます。

paruを機能させるには、GNOME環境で初回起動時の話ですが、

1. shellyを起動させる
2. fuseが必要とでてくるので、そのまま入れる
3. flatpak、AUR、AppImageなど必要と思うものを有効にする
4. 準備が完了したら検索欄でparuを検索してインストール

こういった流れになります。設定ができているようであれば普段は4番のようにしてパッケージの検索から作業を行います。
Shellyは上記であるように、flatpak、AUR、AppImageも扱えるパッケージマネージャです。GNOMEのドックにも入っているホタテ貝のようなアイコンがそれです。
検索してチェックを入れて「インストール」ボタンで単体パッケージは入りますし、ターミナルからのコマンド入力を嫌っている人でも、簡単な操作で目的のものを入れられるようになっています。
複数パッケージをまとめて入れたい場合は、目的のものにチェックを入れて、次の検索をしまたチェックを入れていきます。
いくつチェックしているかも表示されており、それらで確認してインストールボタンを押せば、それらが一覧となってインストールの進捗を見ながら導入できるようになります。

ここでは、paruを入れるついでに、LocalSend、fcitx5も入れたいところですが、LocalSendはShellyで入れるとしてもfcitx5はparuが入れば、

```bash
paru -S fcitx5-im fcitx5-mozc
```

だけで済むわけですから、Shellyでflatpak版と公式リポジトリ版の2種類を気にしながら探すことを考えると、paruで入れるほうが逆にわかりやすいまであります。

> fcitx5-im
> これはArch系でだけ通用するパッケージのグループ名です。ディストリビューションがArch系以外では、fcitx5-gtk、fcitx5-qt、fcitx5-configtool、またディストリビューションで別途必要とされるパッケージをそれぞれ入れる必要があります

> video-downloaderについて
> 唐突に出てきたアプリですが、たまたま気がついたので書き置く次第です。
> shellyの左端に縦に並んでいるアイコンは上から公式リポジトリ、AUR、flatpak……と並んでいます。もしshellyでvideo-downloaderを導入しようとした時、公式リポジトリの方ではアプリ画面内に<u>進捗が表示されず</u>(バーの動作はある)、アプリ的に動作はしているようですが、どういう状況かがわからないので、**flatpak版の方をオススメ**します。
> このように公式の方のが良いのかそれ以外のリポジトリから入れるかは入れてみないと状況がわからないのもありますし、バージョンによって変わるものもあるかも知れません。
> video-downloaderは1つの動画を1つしかダウンロードできず、1つ2つとウィンドウを開いたら並行ダウンロードはできるものの画面も小さいながらも占有してしまいます。一方AppImageの[Open Video-downloader](https://jely2002.github.io/youtube-dl-gui/)は、リンクをコピーするとクリップボードのURLを監視しているので取得できたらAdd(追加)ボタンは押さねばならないものの、登録したリストの動画・音楽ファイルを指定数だけ一挙に同時ダウンロードできるので便利です。しかし、タイトルが長すぎたりなど何かしらの影響でダウンロードできないものもあります。
> video-downloaderはそういうOpen Video-downloaderでダウンロードできないものもダウンロードできたり一長一短です。困ったら中間の位置ぐらいにある[prabolic](https://flathub.org/ja/apps/org.nickvision.tubeconverter)も候補に考えてみてはどうでしょうか？parabolicは以前flatpak版はエラーが出て起動しなかった時もありましたが、現行では開けるようになっているはずです。

### Caelestiaの正しいインストール方法

[caelestia-dots/caelestia](https://github.com/caelestia-dots/caelestia)

まずは、上記リンク先にもあるようにターミナルから、

```bash
paru -S caelestia-cli
```

として`caelestia-cli`を導入します。その後、

```bash
caelestia install
```

で、shellも含めてHyprlandやその設定、いわゆるドットファイルが正しく入るというわけです。多くがAURからのインストールとなり、選択肢が出てきたり数回パスワードの入力を求められますが、それらが面倒なので指紋認証があると多少マシになるのではないかと。

> また現在(2026/11/8)CachyOSでは、`quickshell-git`が必要な所、公式リポジトリの`noctalia-qs`をparuが選択しに行きます。これだとCaelestiaが起動しないので`quickshell-git`の入れ直し等が必要になります。

#### paruでAURのインストールをすると

paruでAURのインストールが始まると、

- View PKGBUILD? [Y/n] （PKGBUILDを表示しますか？）
- Show diffs for build files? [Y/n] （ビルドファイルの差分を表示しますか？）

などと公式のリポジトリなどからインストールするのとはちょっと違う画面や質問が来ます。これは前回のパッケージを入れてから(あるいは最新の公式版から)、インストールのレシピ(中身)がどう書き換えられたのかの変更点が表示されます。
怪しい変更はないか、どういうふうに変更されたかなどの事前確認が、これらメッセージの意味です。

これを拒否するとたいていはインストールがキャンセルされます。そのためインストールする時は内容がわからなくても見なければいけません。
画面下部に`：`で止まっている時、これは操作の待機をしている状況です。最初の表示で大まかにどう変わってバージョンがどうなったか程度の確認で良ければ`q`を入れるとインストールが始まります。

この時、他に次のような操作ができます

- 次の1行進む: `Enter`キー または `↓`キー
- 次の1ページ（画面ごと）進む: `Space`キー または `Page Down`キー
- 前のページに戻る: `b`キー または `Page Up`キー
- 一番最後まで一気にジャンプする: `G`キー（大文字のg）
- 一番最初に戻る: `g`キー（小文字のgを2回素早く押す）

あまりオススメしませんが、毎回`q`で閲覧を止めインストールに向かうのが面倒くさい場合、

```bash
paru -S --skipreview パッケージ名
```

とすることもできます。パッケージビューの更新内容を見ずにいきなりインストールに進むわけです。AURは個人が管理しているパッケージのため何が行われているかがわかりません。それらを確認することがかなり大切なことなので、できるだけわからずともじっくり見るようにして下さい。

特に、

- `source=()`などと書かれている中身で<u>ダウンロード元のURLはどこか</u>はしっかり確認して下さい
   - Githubの開発元リポジトリとか、変なところから身元のわからないソースを持ってきていないかの確認は大切です。
- `pkgname`や`pkgver`などのインストールしようとしているパッケージの名前、バージョンに不審なところはないかを確認するのも大切です。

単体のパッケージを入れる場合は予め作者の名前なども確認しておくと良いかと思います。同名のパッケージで作者が違うということはあります。しかしそれが全て怪しいというわけではなく開発を引き継いでいたりチームだったりすることもあるので、それらを全部追うのは大切ですが分かる範囲で異常がないという事前に確認することが大切になります。

Arch wikiのあるArch Linuxの[AURのページ](https://aur.archlinux.org/)ではAURのパッケージについてそれらを事前に確認できるようにコメントやダウンロード数などを公開しています。これらも確認しておくとよいでしょう。パッケージ名で検索もできます。

インストールを取りやめる権利を放棄するのは賢い行動だとは言えません。手間ではありますが。

### Caelestia導入の罠

#### Google検索で本体ではなくshellのリンクに当たってしまった

今見てみると、本体(caelestia-dots/caelestia)のページには<u>正しいインストールの手順が書いてあります</u>が、Googleで「caelestia」と検索した時、たまたまそれまでの検索とかも関係するのかも知れないものの、一番トップに[caelestia/shell](https://github.com/caelestia-dots/shell)の方がでてくるのです。

このGithubのリンクではまずcaelestia/shellの導入から書いてあり、下の方にマニュアルでのインストール方法があります。いろいろな問題が解決してからアドレスを見たら**確かに…** となりますが、shellから初めてしまったので更にいろいろな問題にぶち当たりました。
この手の導入はインストールスクリプトで行うか、該当シェルがそれらを担っている事もあるのですぐに気が付かないのもムリがないと言い訳をしておきます。しかし、そうなってもリカバリーができるという点で記事に書き残しておこうかと思ったわけです。

間違っていたわけですが、いざcaelestiaを入れようとした時、

```bash
paru -S caelestia-shell caelestia-cli
```

と、Googleの検索でトップに出てきたshellを最初に入れてしまったのが**間違い**でした。これをすると面倒くさいことが起こります。

caelestiaは、`~/.config/quickshell/caelestia`に色々と入り、それとは別にHyprlandの設定や諸々がインストールされます。それらに合わせて依存関係(必要なライブラリやファイル)が入るようになります。
しかし、上記コマンドだとHyprlandは入りませんし`quickshell/`ディレクトリも作成されません。

こういう事態になるだけならいざ知らず、quickshell(quickshell-git)が必要なのに公式リポジトリにある`noctalia-qs`が入るようになってしまいます。これはparuがデフォルトで公式にあるリポジトリを優先して選択するようになっているらしいのでそれが効いたのでしょう。
話によると、これはCachyOSのパッケージの管理が問題らしいです。GithubのissueによるとCachyOS対応のパッケージも出して欲しいなどという話もあるので、他のディストリビューション(ArchLinux本家やEndeavourOSなど)であればこれら問題はでないのかも知れません。

> CachyOSは独自のチューンがされたパッケージのリストを扱っていたりします。それらも関係しているのかも知れません。本来はその方が代替的にもパフォーマンス的にも良いけれども、Caelestiaではそもそも要求するものはそれではないと言うことです。
> CachyOSがそれらを修正するか、Caelestiaがそれらをわかった上でインストール方法でうまく対応するかですが、いずれもの動きが今のところ無いという状況です。

しかし同じ機能があるとは言え、必要なのは`~/.config/quickshell/`でnoctalia-qsではそれらが**できない**わけです。`caelestia shell -d`とデーモン起動させる時にも「`~/.config/quickshell/caelestia`が無い」とWarningがでます。

そこで、quickshell-gitを入れたいと考えるのが普通ですが、`noctalia-qs`を削除しようとしてもcaelestia-shellとの<u>依存関係が崩れるので削除できない</u>というようなメッセージが出ます。
そこで`sudo pacman -Rdd noctalia-qs`で強引な削除を行います。`-Rdd`は依存関係を無視して削除するという荒業です。

対処法としては、まず不要な`noctalia-qs`を削除したので、その後に新たにAURから`quickshell-git`を入れます。

```bash
paru -S --aur quickshell-git
```

しかし前述したように、**これではHyprlandとその他が入らない**のです。shell部分だけが元に戻ったという全くの遠回りとなりました。

全くの遠回りでした。Googleの検索で「caelestia」と検索しているのにわざわざ「<u>caelestia-shell</u>」をトップに出さなくても良いんじゃないのかと。caelestia公式でも全体をインストールする時は、その正しいリンクを貼っておいてから、<u>shellのみを入れたい場合</u>はこうやって入れますと開発者向けの説明を書けばいいじゃないかと思うわけです。
これが日本語で説明が書いてあったのであればもっと早くに「おや？」と思ったのでしょうが、英語でインストールの方法などそれっぽいことが書いてあったのが迷った原因でした。それらは自分の語学力が低いとも言えますが、Googleよ、お前は違うだろと。caelestia-shellと検索してはじめてその結果だろうと。

間違うきっかけはGoogleでしたが、

- 導入方法がRice環境で各々違っているものの同じような名称を使っている
- それが何をするものかの説明が足りない
- 間違いに気がついて正しくインストールしたあとにも罠がある

こういう事が<u>面倒くさい手間が増えた原因</u>でした。

おそらく正しい方法でインストールする中にも、「〇〇」を選択していたら正しく入っていたと言う道もあったのかもしれません。
しかしデフォルトでインストールを進めたら正しく完了する、これが正しい流れだと思います。オプション的に変更を加える場合のみ選択肢からそれらを選べるというのが本来の流れだと思うのです。

こういう事を知らない人が導入したら、ただの何もないデスクトップが表示されるだけで、え？どういうこと？となるだろうと思います。

これらが正常にできたら(caelestia-cliは入っているので)、ターミナルから

```bash
caelestia install
```

として、本体をインストールします。この中で本来必要なものが入ります。caelestia-shellもここで入るわけです。
既に入っているものはスキップされるのでquickshell-gitもそのままでインストールが進みます。

つまり、本来の手順からいろいろすっ飛ばして、途中から始めてしまったわけですが依存関係が正しくなっていれば動作に問題はありません。
正式なインストール手順の通り、

```bash
paru -S caelestia-cli
caelestia install
```

後はメッセージに従っていく。それだけのことですが、上記の罠(quickshellの件)はCachyOSではもちろんあって、これらを行った後noctalia-qsを削除して、quickshell-gitを入れ直すという罠の解消は通る道です。
以前Caelestiaを試した時は、EndeavourOSで入れたのでしょう。現行のEndeavourOSで同じ事が起こらないとも限りませんが、この手の問題にぶち当たったことはなかったと記憶しています。

## インストールを終えたら

Caelestiaを正しくインストールした後もやることがあります。
Caelestiaはインストール直後キーボードの配列が**英語キーボード配列**になっています。アルファベットを入力するのは日本語キーボードの配列と変わりませんが記号などが印字されているものとは違って配列が異なるのはかなり大変です。ハイフン、アンダーバー諸々それらを入れる箇所は多いのにそのままだと基本的な修正をする場合すら大変です。

1. 通常正しくインストールができていたら、再起動もしくはログアウトしてログイン画面でHyprlandセッション(GNOMEの場合は右下のギアアイコンから)を選択してログインします。
2. 自動的にCaelestia shellが起動します

本来であればこうなりますが、私のように回り道をした場合、Hyprlandを選択してログインした後<u>何もないデスクトップが表示されるだけの状態になることがあります</u>。その時のみターミナルから、

```bash
caelestia shell -d
```

と、shellをデーモン起動させる必要があります。正しくインストールできていればCaelestiaの各種バーや機能が働き始めます。
何もないデスクトップではCaelestiaの一切の機能が動作していないのでかなり焦りますが、`Super + E`でファイルマネージャーは機能するはずなので何とかなります。`Super + T(or return)`が機能するのであればターミナルも動作するはずです。
ファイルマネージャーしか起動しなくても右クリックからターミナルで起動というメニューは動くはずですからそれらでも大丈夫です。

Caelestiaさえ機能すればアプリも`Super`(window/⌘キー)で一覧が出ますし普通に使い始められると思います。

### しかし日本語キーボード配列にはしなくてはならない

英語配列だとアルファベットなどは良いですが記号の位置などが異なっているので、日本語配列が必要になる人がほとんどだと思います。
通常であれば、`~/.config/hypr/`の中のファイルを操作します。
ファイルマネージャーを起動するとユーザーのホームディレクトリが表示されていると思いますが、そこで`Ctrl + H`を押すと隠しフォルダが表示されます。そこに`~/.config/`や`~/.local/`、`~/.cache/`などいくつかが新たに表示されるはずです。

しかし、`~/.config/hypr/`の中のファイルを操作すると、このディレクトリはHyprlandの大本の設定ファイルなので<u>アップデートなどでユーザーの変更したものが失われます</u>。
そのため**大本のHyprlandの設定は変更せず** 、別途`~/.config/caelestia/`にあるファイルにユーザーカスタム設定を追記して、その内容で大本の設定を上書きし、アップデートをしてもユーザーが修正したものが失われないという手法が取られています。
これらの仕組みは多く使われており、ディレクトリが違うだけというのがほとんどで、Duxでもend-4でも他のドットファイルでも用いられている手法です。

元々がキーボード配列が英語のため、設定を書くのであれば**一時的に**大本の`~/.config/hypr/hyprland/`にあるinput.luaのキーボード設定をusからjpに変更します。
もし設定がどこかに書いてあって(下記の`hypr-user.lua`サンプルみたいに)<u>それらをコピペできるのであれば一時的なキーボード配列の変更は不要</u>です。
これらは一時的にしろ設定を書くのであれば日本語キーボード配列である必要があり、設定を書いた後はusに戻しておくような順になります。

- 設定ファイルを書く必要があるが、<u>Caelestiaが入っているPC以外で</u>この記事などを見ている時、**コピペが困難な場合がある**のでCaelestiaのPCでは設定を書く必要がある。そのために、
   1. 大本の`~/.config/hypr/hyprland/input.lua`のキーボード設定をus→jpに一時的に変更する
   2. `~/.config/caelestia/hypr-user.lua`に下記のようにして新たに日本語キーボード配列の設定を書く → 保存したら即反映
   3. 変更した1番目の設定を再度 jp → us に戻して日本語のキーボード配列になっているか確認
      - `=`や`_`、`()` などがいつもと同じように打てるなら状態確認ok

### ~/.config/caelestia/にあるファイルの説明

#### hypr-user.lua

既存の設定項目にないHyprlandの設定や、自分で追加する処理を書く

- キーボード配列
- fcitx5の起動
- 環境変数
- 独自キーバインド
- ウィンドウルール

サンプル的には、

```lua
-- キーボード配列
hl.config({
    input = {
        kb_layout = "jp",

        touchpad = {
          natural_scroll = false,
        },
    },
})

-- IME環境変数
hl.env("GTK_IM_MODULE", "fcitx")
hl.env("QT_IM_MODULE", "fcitx")
hl.env("XMODIFIERS", "@im=fcitx")

-- 起動時の処理
hl.on("hyprland.start", function()
    hl.exec_cmd("fcitx5 -d")
end)
```

IMEの環境変数は私の場合、特に必要ありませんでしたが、従来通り、`hl.env("XMODIFIERS", "@im=fcitx")`は書いておいてもいいかと思います。

- fcitx5の現在の設定では環境変数は書かないで問題ないなら書かないのがデフォルトです
   - 書いた場合、「環境変数が書いてあるけど不要なんでwiki見てね」というような通知が来るようになります。
   - 通知が来るだけで支障がないならそのままで使用してもよいですし、いちいち通知がログインするたびに出るのは邪魔だと言うなら書かない方向で
- XMODIFIERSの設定は古いX11対応のアプリで全部ではありませんが問題が出ることがあるので念のために書いておくというようなおまじないみたいな感じです

起動時の設定はログインした時の設定なので、これを書いた後ログアウト→ログインとすればこの設定が読み込まれますが、それまでにfcitx5を起動するのであればfcitx5そのものをアプリで起動するか、ターミナルで同様に`fcitx5 -d`を入れます。

よくわからない場合は上記を該当ファイルにコピペ(あるいは書いて)、再ログインすれば良いだけです。

#### hypr-vars.lua

Caelestia側で既に変数化されている設定を変更します。通常は変更する必要はありません。

- ウィンドウの隙間
- ウィンドウの角丸
- キーバインド
- デフォルトアプリ

サンプル的には、既にファイル内に`return { }`が記載されているので、その中に記載して最終的には次のようになるようにします。

```lua
return {
    -- Gaps
    workspaceGaps = 12,
    windowGapsIn = 3,
    windowGapsOut = 6,
    singleWindowGapsOut = 12,

    -- Window styling
    windowRounding = 10,
    windowRoundingPower = 2,
}
```

ここでいう角丸は各アプリケーションウィンドウそのものの角丸です。CaelestiaのUI等とは別の設定です。
各値はCaelestiaのGithubにリンクがあります。→ [variables.lua](https://github.com/caelestia-dots/caelestia/blob/main/hypr/variables.lua)

#### shell.json(必要な場合は作成)

これはQuickshellで構成されるCaelestiaのデスクトップUIを変更するための設定を書きます。

- バーやランチャー
- shellのフォント
- shell内の余白
- shellの角丸
- アイドル時の動作

標準設定では、

|アイドル時間|動作|
|:---:|---|
|3分|画面ロック|
|5分|ディスプレイオフ|
|10分|サスペンドしてからハイバネート<br>suspendThenHivernate|

これらを次のように変更します。

- バッテリー駆動時：10分でロック
- 30分でディスプレイOFF
- 60分でスリープ
- 充電中：これらのアイドル動作を抑制

```json
{
    "general": {
        "idle": {
            "lockBeforeSleep": true,
            "inhibitWhenCharging": true,
            "timeouts": [
                {
                    "timeout": 600,
                    "idleAction": "lock",
                    "inhibitWhenCharging": true
                },
                {
                    "timeout": 1800,
                    "idleAction": "dpms off",
                    "returnAction": "dpms on",
                    "inhibitWhenCharging": true
                },
                {
                    "timeout": 3600,
                    "idleAction": ["suspendThenHibernate"],
                    "inhibitWhenCharging": true
                }
            ]
        }
    }
}
```

しかし、Caelestiaでは、`Super + N`で画面右側に出るパネル(画面右下にカーソルを持っていっても一分表示)から<u>Keep awake</u>というGNOMEの拡張機能で言うCaffeinのような機能があります。これらを手動で切り替える運用をするのであれば、上記shell.jsonの設定は不要かもしれません。**必要に迫ったら実装してください**。

同じパネルからギアのアイコンで各種簡易的な設定ができるウィンドウが表示されます。未実装の部分も多くあり現時点ではAuto設定になっているので細かいカスタマイズはshell.jsonやその他ファイルを直接編集して行う感じになっています。

#### フォントなどは？

これはフォントを選べる設定のあるアプリであれば多くは問題ないですが、それらがない場合GNOMEのデフォルトがAdwaitaだったように思うので、これを変えたいと言う人もいると思います。

これらも変更できますが、fontconfigの記述を間違えると色々大変になることがあります。もし設定を間違ったら全体的にフォントが
豆腐になってしまい何が書いてあるのかがわからなくなるため、<u>超能力者になるぐらいのスキルが必要になります</u>。これらを直すためttyでなんとかするか、CachyOSのライブISOから起動して`cachy-chroot`だったかで該当のストレージ領域に入って直すというLinuxを使用している一般的なユーザーよりも圧倒的な上級者以上のスキルが必要になります。
修正したと思って実際に起動したらまだ豆腐だとかと言うこともあり、これは危険とも言えます。真っ白なジグソーパズルでもピースの形が違いますが、フォントが全部豆腐ということは確実な自分の記憶と一切間違いのないコマンドの入力が必要になり、その結果で表示されるメッセージですら豆腐ですから、それらも予測して手探りで全てを操作しないといけません。
こうなったらたいていはクリーンインストール推奨となります。画面が割れているPCを操作するよりはちょっとだけマシ程度で、エスパー級のスキルが必須ですから時間をかけるよりもやり直すのが圧倒的に早いと言う残念な結果につながるわけです。

オススメとしては今回はGNOMEで入れているのでGNOMEの**Tweeks**というアプリでフォントを変更する方が安全だと思います。

1. `~/.local/share`に`fonts`と言うフォルダーを作ります。ファイルマネージャーでディレクトリを辿ってWindowsで操作するようにすればユーザー領域なので作れます。
   - localとあるように、このフォントはログインした後に使用・表示されるフォントだということに注意してください
2. `~/.local/share`に各種使用したいフォントを入れます。
3. Caelestiaで`Super`を押し、ランチャーから tw 辺りまで入れれば候補を絞れるのでTweeksが選択・起動できます
4. フォントを好きなものに変更する 

リアルタイムに変更されると思うのでフォントサイズなどを変更し、自分で良い感じになるように調整してください。

TweeksはあくまでGNOMEの設定を敢えて変えるならという位置づけの、もしかしたらその内に無くなったり別のものに置き換わったり何かしらあるかも知れないようなものですが、2026年11月現在は使用できるので簡単に設定できなら使ったほうが早いと。
ただし、これはGNOMEのものであるため、GNOMEの設定を変更したら全てのアプリなどで変更が反映されることを保証したものではありません。大雑把には変わるだろうという程度のものですが、だいたいそれぐらいで結構印象は変わると思います。

#### スクリーンショットはどこに？

`Super + N`で画面右側に出るパネルがあると前述しましたが、そこにスクリーンショットの設定などがあります。

便利に使うためには他のスクリーンショット・キャプチャ用のアプリを導入してその操作に従う必要があるのでしょうが、画面全体を撮るか、部分的に撮るかなどを指定しておいてキーボードの`Print`(Print Screen)キーで撮ることができます。

撮ったスクリーンショットは、`~/.cache/caelestia/`の中にスクリーンショットのフォルダがあるのでそこに入っていきます。

## なぜCaelestiaなのか

本題は、<u>Dux shellのキー入力の問題は他の環境でも起こるのか？</u>ですが、同じquickshellを使用していながら実装方法が違うcaelestiaでどうなるのだろうかがポイントです。
これでも同じようにキー入力の問題が発生するならそれはシェルの問題ではなく、もっと低レベルのquickshellやQMLの新しくなった動作環境にDux shellやらが追従できていないのではないだろうかという仮説です。
Dux shell自体は正しく動作するように実装しているけれども、quickshellにそもそもの原因があってそれを捌ききれていないのではないだろうかと言うことです。

Dux shellはバックエンドがGo言語で書かれており、おそらくcaelestiaはC++とLuaで書かれており、Duxはwayland全般的に色んなコンポジターに対応していますが、caelestiaはHyprlandと密に設計されています。

<div class="table-container">

|　|Dux shell|Caelestia(caelestia-dots/shell)|
|----|----|----|
|ベースフレームワーク|Quickshell(Qt6/QMLベース)|Quickshell(Qt6/QMLベース)|
|画面・UI|QML(JavaScriptベース)|QML(JavaScriptベース)|
|バックエンド・ロジック|Go言語|C++(一部)&Lua言語(設定等)|
|想定WM|Wayland(全般)|Hyprland(ほぼ専用)|

</div>

このように、バックエンドなどが違うだけで見た目はほぼ同じQuickshellなどを使用して作られています。
もし、Dux shellで問題が出ることをCaelestiaがクリアしているとなると、その実装方法をGo言語で置き換えれば(ただそれだけではダメでしょうが)問題点を改善できる足がかりになるのではないだろうか？と考えたわけです。

CaelestiaでもDux同様に問題が出るとすれば、それはQuickshell周りがとても怪しくなります。Quickshellに問題があるとして、QuickshellがアップデートされればDuxなども連動するように問題が解決されるのが一番わかりやすく良いですが、Quickshellには問題がないとすると今度はCaelestiaの実装方法を解析して置き換える必要があります。

問題がどこにあるのかを知るためには、Duxだけを使用していると全くわからずジャーナルでログを取ってみても問題点らしき部分は見えても、それが原因と特定できるようなものではありません。
これまでの報告で出ていた問題点は確かにfixされているので被害は軽微に、特定の場合に発生して、比較的早くに回復すると言う現状にはなっているけれども、ここが原因だとはわからずじまいなわけです。

ましてや英語圏ユーザーがfcitx5などを使用して文字入力で英語<-->日本語と操作を行ったり来たりして使用しているわけではなく、おそらく英語環境だと問題が出にくいんだろうとも思います。

今回の試みはできるだけこれらが解決されるように、試す価値のある方法ではないだろうかと。Caelestiaが今どうなっているのかを試してみたかっただけと言う側面もありますけれども。

## GNOMEの最新版を使用して気がついたこと

言われてみれば当たり前のことですが、電源メニューに<u>ログアウトが無い</u>というのに気が付きました。これは、

- 自分以外のアカウントがない
- 他のセッションもない
   - HyprlandやCOSMICが別で入っていないので起動するのはGNOMEのみという環境

これらの場合にログアウトは出ない仕様のようです。前にCOSMICを使用していた時(Fedora環境)では、単一のアカウントしか無い時もログアウトボタンがあったように思うので勘違いをしていたのかも知れませんし、もっと前にGNOMEを使用していた時、Dux(旧Dank Material Shell)が入っていたりHyprlandの環境があったので、それらセッションのおかげでログアウトがあったのかも知れません。
しかしこれらが勘違いでないのなら、v50+になってそういう表示になるように変更されたのかと思います。

### v50+で変更された所

- Waylandオンリーとなり、「X11(Xorg)のセッション」がディスプレイマネージャー(Mutter)から完全に削除されました
- ゲームや画面共有の最適化が行われ、Waylandへ完全移行したため可変リフレッシュレート(VRR/FreeSync)や分数スケーリング(Fractional Scaling)が実験的機能から、安定動作する機能へと昇格しました
- ディスプレイマネージャー(Mutter)の改良でCPUが高負荷な場合でもアニメーションやスクロールがカクつきにくくなる大幅な改良が入っています
- v50からファイルマネージャー(Files)の画像読み込みライブラリが新世代のGlycinに刷新され、サムネイルの生成速度が爆速になりました。
- v50からですが、子どもが使用する際にそのスクリーンタイムを監視したり、ベッドタイムで自動ロック等がシステム標準として本格的に組み込まれました
- v51から、複数ファイルをドラッグした時に個数がバッジ表示される(Drag Count Badge)機能や、コピーしたファイルが自動選択される機能など、操作感が現代風になりました
- NVIDIA対応が強化され、v51からはNVIDIA環境でも極めて滑らかに動くようになっています
- v51からは、モニターごとの輝度が再起動後も維持されるようになりました
- スペースキーでファイルの中身が覗ける`Sushi`がv51でGTK4で完全に書き直されました。カレンダーアプリの動作が極端に多い予定でもそれらのスクロールなどがスムーズになっています
- v51から指紋認証管理画面のUIが刷新され、よりわかりやすいUIとなりました

これら一部は些細なアップデートですが、操作感はそのままにわかりやすくなるのは良いと思えます。


## まとめ

再度手順を書いておきます。

1. caelestia-cli をインストール
2. caelestia install
3. Hyprlandセッションでログイン
4. Shellの自動起動を確認
5. 日本語キーボード配列
6. fcitx5の起動設定
7. (任意)ギャップ・角丸などの調整
8. (任意)スリープ・電源設定
9. (任意)キーバインドの追加・変更

このような感じです。

インストール直後に何もないHyprland画面が出た場合、まずShellの自動起動が機能しているか確認します。そこで初めて手動起動を試す、という順番が正しいです。
また、`~/.config/hypr/`は基本的に編集せず、個人設定は`~/.config/caelestia/` に集約します。

`hypr-user.lua`のサンプルで念のためIMEの環境変数も書きましたが、GTK_IM_MODULESは通知が出ます。QTも設定するとそれだけが原因ではないでしょうが動作が不安定になりました。よって、やはり、`XMODIFIERS`の設定だけにとどめておくべきだと思います。

Tweeksでフォントを変更した時に、例えば動画のサムネイルなどとファイル名の行間が広くなる場合がありそうです。フォントはリアルタイムに変更されるけれども行間などはリアルタイムで更新されず、一旦閉じて再度開いたとしてもキャッシュがあるのか見た目の変化はありませんでしたが、ログインし直すとそれらは解消されていました。

動画を見る場合、色々なプレイヤーがありますがフレームレスなMPVをHyprland他Waylandコンポジターではオススメしています。その際のMPVの設定は、[MintやUbuntuをWindowsの代替に使うのは止めてFedoraにしとこう](/blog/exploring-linux-options/) → DMSのインストールが終わったら → MPVの設定ファイル に書いてあります。
これを<u>mpv.conf</u>とファイル名をつけ、`~/.config/mpv/`の中に入れてください。

ターミナルのプロンプトには、[starship](https://starship.rs/ja-JP/)というものが使用されています。starship公式にもいくつか例がありますしGithubにもディスカッションとかにサンプルが投稿されているページがあったと思います。あるいはRedditなどにも投稿されているものがあると思います。
これらはその設定ファイル(`starship.toml`)が`~/.config/`直下に置いてありますので、念のため元々あったものをリネーム(starship.toml.bak等)するかどこかわかる所に退避して、拾ってきたファイルを入れ替えればプロンプトが飾れます。
